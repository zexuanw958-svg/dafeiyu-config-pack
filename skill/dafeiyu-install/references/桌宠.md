# 电脑桌宠也变成她（可选，装完以后）

DeepSeek Harness（DSH）有个很火的桌宠插件 dsh-pet（github.com/PC2005-cloud/dsh-pet），桌面上趴着一只鲸鱼娘，右键能跟她聊天。它本来用自己的人设（「蓝毛小女仆」）和 DSH 的模型回话，跟 QQ 里的她是两个人。

接上以后：桌宠里跟他说话的就是 QQ 里这个她，同一份人设、同一个 DeepSeek、同一套本事（记住事、定提醒）；长期记忆跟他的 QQ 私聊共用一份，QQ 里说过的事桌宠里也知道，反过来也一样。

这期视频不教怎么装桌宠。**他没装 dsh-pet 就不提这件事，也不劝他去装。**

## 什么时候提

- 第 9 步验收全部通过以后，体检里 `agents.dshPet.installed` 是真、`linked` 是假（摘要「AI 帮手」那行写着「装了桌宠插件 dsh-pet，还没接成她」），问一句：

  > 我看到你的 DeepSeek Harness 里装了桌宠。要不要让桌宠也变成她？变了以后，你在桌宠里跟她说话，跟在 QQ 私聊里是同一个她：QQ 里聊过的事她在桌宠里也知道，反过来也一样。

  他问代价，照实说：电脑上多一个很小的后台程序（「大肥鱼桥」，不出窗口）；桌宠里聊天跟 QQ 私聊一样花 DeepSeek 余额；DSH 开着桌宠才在（关掉 DSH 窗口只是收进托盘，桌宠还在）；桌宠只显示文字，不发语音、不配表情包。他说不要就不做，以后想要再说。
- 他自己说「让桌宠也变成她」「桌宠也要是大肥鱼」：先看 `%USERPROFILE%\.dsh\dsh-pet\` 在不在（或者体检的 `agents.dshPet`）。不在就说：「这个要先在 DeepSeek Harness 的『插件管理』里装好桌宠插件 dsh-pet，装完退出 DSH 再打开。装好了跟我说一声，我接着弄。」不替他装。
- 选了「只拿几样」的、换成了自己角色的也能接：桌宠里就是他的那个角色。名字跟着改：`setup-pet.ps1` 默认把桌宠叫「大肥鱼」，他的角色叫别的，你就照下面「换成别的名字」那条改。

## 怎么接

先确认她在 QQ 里能正常回话（第 6 步过了）。然后：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<S>\setup-pet.ps1" -Dir <工作目录>
```

不用下载，半分钟左右。它做四件事：

1. 后台建一把只给桌宠用的接口密钥「大肥鱼桌宠」（只能用来跟她聊天），存进 `private\pet-key.txt`；再生成一个桌宠调桥用的口令 `private\pet-bridge-token.txt`。已经有、还能用就不重建。
2. 装「桌宠互通」插件（`astrbot_plugin_dafeiyu_petlink`），记忆改成「QQ 私聊和桌宠共用一份」（下面「记忆怎么分」）。
3. 「大肥鱼桥」拷进 `<工作目录>\tools\`，后台跑起来（只听本机 `127.0.0.1:26199`，要口令），开机自启（启动文件夹「大肥鱼-桌宠桥」，不出窗口）。
4. DSH 里登记一个自定义模型「大肥鱼（QQ 同款）」（写 `%USERPROFILE%\.dsh\profiles\<装了 dsh-pet 的那个>\cordis.patch.yml`，口令写进 `%USERPROFILE%\.dsh\.credentials.yaml`），dsh-pet 的对话模型选它，名字改「大肥鱼」，人设换成精简版的她（写 `%USERPROFILE%\.dsh\dsh-pet\main-config.jsonc`）。三个文件改之前都备份（`*.dafeiyu-bak`），改了什么记在 `%USERPROFILE%\.dsh\dsh-pet\dafeiyu-pet-original.json`，拆掉时照它还原。他自己加过的别的自定义模型原样留着。DSH 开着一般不用重开：自定义模型和口令它几秒内自己读到，桌宠的名字和人设脚本会让它重载（万一没认出来，脚本报 `reason=restart-dsh`，见下面）。

**成功**：最后一行 `RESULT pet=ok`。工作台多了一项「桌宠」，亮绿灯。
**`reason=restart-dsh`**：DSH 还没认出新加的模型。跟他说：「最后一步要你把 DeepSeek Harness 退出再打开（右下角托盘图标右键退出），我们这次对话会断，没关系，打开以后直接去跟桌宠说话就行。」先把验收要他说的话交代完再让他退。
**`reason=dsh-manual`**：DSH 的设置文件写法跟我们认的不一样，脚本没硬改。照下面「手动填」带他在设置页里点。
**输出里有 `MIGRATE private-memories`**：他以前在 QQ 私聊里让她记住的事要搬一下，见下面「旧记忆搬家」。

## 验收

1. 桌宠右键 →「对话」，问她「你是谁」：回答是她的口气，不是「蓝毛小女仆」。
2. 刚聊过的事两边通：在 QQ 私聊里跟她说「我中午吃了螺蛳粉」，再去桌宠里问「我中午吃的啥」，她答得上；反过来在桌宠里说一件，去 QQ 私聊里问。这靠互通插件：对面最近 12 小时里新说的几句（最多 8 条）会带给她。
3. 长期记忆通：在桌宠里说「记住，我下周三考科目二」，去 QQ 私聊发 `/reset`，再问「我哪天考科目二」。
4. 提醒：在桌宠里说「两分钟后提醒我喝水」，到点 QQ 私聊收到提醒。要看、要取消提醒，去 QQ 私聊里说（桌宠里定的提醒挂在 QQ 私聊上）。

## 记忆怎么分（导入记忆以后，接没接桌宠都是这样）

- 他的 QQ 私聊和桌宠：一份。
- 每个群：各记各的，群里的事不会跑到私聊里，私聊的事也不会在群里说出来。
- 没登记过的群、陌生人：不记（宁可健忘，不串台）。让她进群时跑的 `astr_setup.py ... whitelist` 会把群同时加进记忆的「强制隔离」和「记忆白名单」。
- 桌宠自己隔一会儿冒出来的那句碎碎念：用的是 DSH 自己的模型和精简人设，不进她的记忆，也不进 QQ 那边的对话。

改的是 LivingMemory 的三项：`filtering_settings.memory_scope_mode = global`、`filtering_settings.isolated_sessions`（每个群一行）、`access_control.whitelist_enabled = true` 加 `access_control.allowed_ids`（他的私聊、桌宠、登记过的群）。单独重设：`astr_setup.py --dir <工作目录> memory-scope`。`astr_setup.py ... status` 的「记忆范围」那行能看现在是什么样。

## 旧记忆搬家（以前装过记忆的）

记忆以前是「一个会话一份」，改成共用以后，他以前在 QQ 私聊里让她记住的事还在旧位置，她召回不到。导入或 `setup-pet.ps1` 输出 `MIGRATE private-memories` 时，你替他搬（只搬私聊那份，群的不动）：

```powershell
& "<AstrBot 的 Python>" -X utf8 "<S>\astr_setup.py" --dir <工作目录> memory-migrate          # 先预览：会搬几条
& "<AstrBot 的 Python>" -X utf8 "<S>\astr_setup.py" --dir <工作目录> memory-migrate apply    # 真搬；插件搬之前自己备份数据库
```

跟他说一句就行：「你以前让她记住的事，我搬到新位置了，QQ 和桌宠都用得上。」

## 手动填（脚本报 dsh=manual 时）

照他屏幕上的字为准，大致是：

1. DSH 设置 → 模型 →「自定义模型 API」→ 新增：服务商 ID 填 `dafeiyu`，名字「大肥鱼（QQ 同款）」，协议选 OpenAI Chat Completions，地址 `http://127.0.0.1:26199/v1`，模型 ID `dafeiyu`。API Key：用 `notepad <工作目录>\private\pet-bridge-token.txt` 打开，让他自己复制粘贴进去（你不念出来）。
2. 桌宠的设置页：对话模型选「大肥鱼（QQ 同款）」；名字改「大肥鱼」；「人设」框里的内容换成 `<S>\pet-persona.txt` 里那几行（同样记事本打开让他复制）。
3. 右键桌宠点「重载配置」。再跑一次 `setup-pet.ps1 -Dir <工作目录> -Check` 看是不是都对上了。

## 换成别的名字（他换成了自己的角色）

`setup-pet.ps1` 不认角色名。接好以后再跑一次 `pet_config.py`，把名字和人设换成他的：

```powershell
& "<AstrBot 的 Python>" -X utf8 "<工作目录>\tools\pet_config.py" apply --token-file "<工作目录>\private\pet-bridge-token.txt" --name "<角色名>" --persona-file "<你写的精简人设文件>"
```

精简人设是桥连不上时桌宠回落用的（三四行：她是谁、什么性格、怎么说话、不做什么），照他角色包的人格写一份，存成 `<工作目录>\tools\pet-persona-mine.txt`（不含秘密，别放进 `private\`）。以后重跑 `setup-pet.ps1` 会改回「大肥鱼」，记得再跑一次这条。

## 它是怎么接的（排错用）

```text
桌宠（dsh-pet，右键「对话」）
  │ DSH 的自定义模型 dafeiyu → http://127.0.0.1:26199/v1（OpenAI Chat Completions 格式，带口令）
  ▼
大肥鱼桥（<工作目录>\tools\dafeiyu_pet_bridge.py，只认本机来的请求）
  │ 只取他最后说的那一句；dsh-pet 自带的人设、聊天历史、表情包清单都不转
  ▼
AstrBot 开放接口 POST /api/v1/chat（密钥「大肥鱼桌宠」，范围 chat + chat:admin；以他的大号说话，会话 desk-pet）
  ▼
她：大肥鱼人设 + DeepSeek + 记忆（跟 QQ 私聊同一份）+ 记住、提醒这些工具
```

- 桌宠的会话在后台「会话管理」里叫 `webchat:FriendMessage:webchat!<大号>!desk-pet`。互通插件把它的语音关了（只显示文字，豆包按时长扣钱），想开在那里改。
- 桌宠这边一次回完，不像 QQ 里那样一句一句隔几秒发（气泡要等整段回完才显示，分段只会让她晚好几秒出声）。互通插件的「桌宠那边一次回完，不分段」管这个，QQ 里照旧分段。
- 桥连不上她（大脑没开、密钥被删）时回一个错误，dsh-pet 会自动回落到 DSH 自己的模型再答一次，用的是精简人设，所以还是她的口气，只是不知道 QQ 里的事。
- 桥的日志：`<工作目录>\logs\pet-bridge.log`（只记长度和用时，不记聊天内容）；启动失败看同目录 `pet-bridge-run.log`。
- 碎碎念要是被设成走桥（dsh-pet 设置里「碎碎念模型」选了大肥鱼，或者 DSH 主对话的模型选了大肥鱼），桥会把它放进单独的 `desk-pet-whisper` 会话，不挤进他的聊天，也不进记忆。默认不走桥。
- DSH 的模型列表里会多一个「大肥鱼（QQ 同款）」，它只给桌宠用。他要是在 DSH 主对话（让 AI 干活那个）里选了它，桥会拒掉（主对话的请求带工具清单，桌宠的不带），DSH 那边报错「大肥鱼只在桌宠里说话」：让他把主对话换回 DeepSeek 的模型。

## 失败先查

- 工作台「桌宠」黄灯「大肥鱼桥没在跑」：点「重开大肥鱼桥」。重开还不行，看 `pet-bridge-run.log` 最后几行。
- 桌宠回话还是「蓝毛小女仆」的口气：`setup-pet.ps1 -Dir <工作目录> -Check` 看哪项没对上，重跑 `setup-pet.ps1`；还不行走「手动填」。
- 桥的日志里一直是「失败（……），交给 dsh-pet 回落」：先看工作台「大脑」那项开没开；大脑好好的，跑 `setup-pet.ps1 -Dir <工作目录> -Check`，说「连不上她的大脑（key）」就重跑 `setup-pet.ps1`（会重建密钥）。
- 端口 26199 被别的程序占了：桥起不来，日志里写着。先问他那是什么程序，别直接关。
- DSH 或 dsh-pet 更新以后又变回小女仆：更新可能重置了设置文件，重跑 `setup-pet.ps1`。

## 拆掉（他说「桌宠变回原来那样」）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<S>\setup-pet.ps1" -Dir <工作目录> -Remove
```

DSH 的自定义模型、口令、dsh-pet 的对话模型和名字人设照第一次改之前的样子还原（凭证文件那份备份里有他别的凭证，一起删掉）；停桥、删开机自启；后台那把「大肥鱼桌宠」密钥作废。互通插件和记忆范围留着，不影响 QQ 里的她。卸载大肥鱼（`uninstall.ps1`）会先自动做这一步。

手动拆：DSH 设置里删掉自定义模型 `dafeiyu`；桌宠设置里对话模型改回「跟随当前模型」、名字和人设改回去；启动文件夹删「大肥鱼-桌宠桥」；AstrBot 后台「API 密钥」里删「大肥鱼桌宠」。
