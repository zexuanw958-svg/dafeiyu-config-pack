# 云端路线：装在云服务器上

> 10-28 实测：服务器是阿里云轻量（北京，2 核 2G，Alibaba Cloud Linux 3，没有代理），观众电脑用 Windows 11（PowerShell 5.1、系统自带 OpenSSH）。C1 生成密钥和试连、C2 体检、C5 起容器到出二维码、C6 传 Skill、C7 设置后台、C8 开隧道和网页后台、C9 导入（core、插件、表情包、Edge 语音）都通了。**没测的**：C1 在云控制台网页终端里粘贴装公钥（要人点）、C4 在 Ubuntu 上装 Docker、C8 扫码以后（登录、连上、掉线）、记忆和看视频。

> 10-29 加了「云端大肥鱼工作台」（C10）：在测试机上装好、打开、查十项、看日志、重启大脑、备份、求助信息都实测通了；扫码只测到二维码能显示。

观众电脑还是 Windows，你（Agent）在他电脑上干活，用 Windows 自带的 `ssh` 连到他买的云服务器（Ubuntu 24.04 或 Alibaba Cloud Linux 3），在服务器上用 Docker 跑 NapCat + AstrBot。设置脚本和导入工具也在服务器上跑（`tools` 容器），他电脑上不用装 Python。

什么时候走这条：观众一开口就说要装云上、或者他已经有一台云服务器；或者看到推荐方案后回「装云上」。本机路线的推荐方案里只带一句「想装到云服务器上（24 小时在线，要交月租）就说『装云上』」，不主动推。

## 先讲清楚利弊（必须讲，别省）

> 装云上的好处：24 小时在线，家里电脑可以关。
> 代价有几个，我先说清楚：
> 1. 更容易被 QQ 踢下线。机房的网络加上小号，是 QQ 最警惕的组合。泽轩试过两台云服务器，一台两小时被踢了两次，一台扫码当场就弹了「账号有安全风险」，得在手机 QQ 上恢复。被踢了要重新扫码。
> 2. 要交月租。首年很便宜，续费常常贵好几倍，买之前一定看续费价。
> 3. 服务器没有显卡，不能用本机语音。语音只能用豆包或者不要。
> 4. 出问题我看不到服务器屏幕，排查会慢一点。
> 想清楚了回「装云上」，我们接着来；改主意也行，装在你这台电脑上就没这些问题。

## C1 连上服务器

### C1.1 他要先准备好

- 服务器的公网 IP：在云厂商控制台的实例列表里。让他用记事本粘进 `<工作目录>\private\cloud.txt` 第一行，写成 `host: 1.2.3.4`。你自己读，别念出来、别显示。
- 确认 `ssh` 在：`ssh -V`。Windows 10 1809 以后和 Windows 11 自带；没有的话在「设置 → 系统 → 可选功能」里加「OpenSSH 客户端」（要他点）。

### C1.2 生成密钥，装进服务器

1. 生成（无密码短语），生成完马上核对：
   ```powershell
   ssh-keygen -q -t ed25519 -N '""' -C dafeiyu -f "<工作目录>\private\cloud_key"
   ssh-keygen -y -P x -f "<工作目录>\private\cloud_key"
   ```
   第二行打出 `ssh-ed25519 …` 一行＝没有密码短语，对了；报 passphrase 不对＝生成时把引号当成了密码，删掉两个文件，改用 `cmd /c 'ssh-keygen -q -t ed25519 -N "" -C dafeiyu -f "<工作目录>\private\cloud_key"'` 重来（PowerShell 7 可能这样）。10-28 在 PowerShell 5.1 上两种写法都实测没问题。
   **别写 `-N ''` 或 `-P ''`**：PowerShell 5.1 会把空串整个丢掉，`ssh-keygen` 就停下来等人输入，你会卡死（10-28 踩过）。
2. 收紧私钥权限，不然 `ssh` 会报「UNPROTECTED PRIVATE KEY FILE」拒绝使用（10-28 实测这样写就行，之后 `ssh` 认这把钥匙）：
   ```powershell
   icacls "<工作目录>\private\cloud_key" /inheritance:r /grant:r "$($env:USERNAME):(R)"
   ```
3. 做一行装公钥的命令，放进剪贴板（公钥不是秘密，出现在屏幕上没事）：
   ```bash
   mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo '<cloud_key.pub 的内容>' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys && echo "OK $(whoami)"
   ```
   用 `Set-Clipboard` 放进去。
4. 停下来叫人：
   > 现在去云服务器的控制台，找到这台服务器，点「远程连接」或者「登录」（阿里云叫 Workbench，腾讯云叫 OrcaTerm），会打开一个黑底的网页窗口。在里面按 Ctrl+V 粘贴，再按回车。看到一行 `OK` 加一个名字，就把那个名字告诉我（一般是 root 或 ubuntu）。
5. 把用户名写进 `cloud.txt` 第二行 `user: …`。
6. 试连（10-28 实测）：
   ```powershell
   ssh -i "<工作目录>\private\cloud_key" -o StrictHostKeyChecking=accept-new -o BatchMode=yes -o ConnectTimeout=15 <user>@<host> "echo ok; uname -a"
   ```

**成功**：打印 `ok`。之后每条服务器命令都这样跑（`BatchMode=yes` 保证它不会卡在等密码）。用户不是 root 的，命令前加 `sudo`，先用 `sudo -n true` 确认免密 sudo（腾讯云 Ubuntu 默认 `ubuntu` 用户能免密 sudo，待实测）。

**失败先查**：
- `Permission denied (publickey)`：公钥没装上。让他在网页终端里跑 `cat ~/.ssh/authorized_keys` 看看有没有那行；用户名对不对（root 和 ubuntu 的 `~` 不一样）。
- 连不上、超时：控制台防火墙（安全组）有没有放行 22；IP 抄错没有。
- `UNPROTECTED PRIVATE KEY FILE`：回到第 2 步。

## C5 起容器

10-28 在阿里云轻量北京（没代理）上照下面从零起过：两个镜像从 DaoCloud 拉，**一共 50 秒**；NapCat 20 秒出二维码。

### C5.1 目录和秘密

```bash
D=/opt/dafeiyu; mkdir -p $D/private; chmod 700 $D $D/private; cd $D
for f in napcat-webui-token onebot-token; do [ -s private/$f.txt ] || openssl rand -hex 16 > private/$f.txt; done
cp private/onebot-token.txt private/napcat-ws-token.txt
[ -s private/backend.txt ] || printf 'url: http://astrbot:6185\nusername: dafeiyu\npassword: %s\n' "$(openssl rand -hex 12)" > private/backend.txt
MAC=$(printf '02:42:%02x:%02x:%02x:%02x' $((RANDOM%256)) $((RANDOM%256)) $((RANDOM%256)) $((RANDOM%256)))
[ -s .env ] || printf 'NAPCAT_UID=1000\nNAPCAT_GID=1000\nNAPCAT_WEBUI_TOKEN=%s\nNAPCAT_MAC=%s\n' "$(cat private/napcat-webui-token.txt)" "$MAC" > .env
chmod 600 .env private/*
```

- `backend.txt` 里的地址写容器名 `astrbot`：设置脚本和导入工具都在容器网络里跑（C7、C9），不经隧道。
- MAC 地址第一次随机生成后写死在 `.env` 里，以后重建容器也不变（推断：让 QQ 不把重建的容器当成新设备）。
- 他的 DeepSeek key 和大号：照本机路线让他用记事本粘进他电脑上的 `<工作目录>\private\deepseek-key.txt`、`owner-qq.txt`，你用 `scp` 拷上去，不经命令行参数、不显示：
  ```powershell
  scp -i "<工作目录>\private\cloud_key" "<工作目录>\private\deepseek-key.txt" "<工作目录>\private\owner-qq.txt" <user>@<host>:/opt/dafeiyu/private/
  ```

### C5.2 compose.yml

```yaml
services:
  napcat:
    image: m.daocloud.io/docker.io/mlikiowa/napcat-docker:v4.18.41
    container_name: napcat
    restart: always
    environment:
      - NAPCAT_UID=${NAPCAT_UID:-1000}
      - NAPCAT_GID=${NAPCAT_GID:-1000}
      - MODE=astrbot
      - WEBUI_TOKEN=${NAPCAT_WEBUI_TOKEN}
      - ACCOUNT=${NAPCAT_ACCOUNT:-}   # 快速登录：扫码登上一次后，工作台「补上」把小号写进 .env，重启不用再扫
    ports:
      - "127.0.0.1:6099:6099"      # 只绑本机
    volumes:
      - ./data:/AstrBot/data
      - ./napcat/config:/app/napcat/config
      - ./ntqq:/app/.config/QQ     # QQ 登录数据，重建容器也留着
    mac_address: ${NAPCAT_MAC}
    mem_limit: 1200m               # 2G 机器；4G 以上可以去掉
    networks: [astrbot_network]
  astrbot:
    image: m.daocloud.io/docker.io/soulter/astrbot:v4.29.3
    container_name: astrbot
    restart: always
    environment:
      - TZ=Asia/Shanghai
    ports:
      - "127.0.0.1:6185:6185"      # 只绑本机；6199 不映射，只在容器网络里用
    volumes:
      - ./data:/AstrBot/data
    mem_limit: 800m
    networks: [astrbot_network]
  # 平时不启动：跑设置脚本、导入工具时临时起一下（docker compose run --rm tools ...），跑完就删。
  # 用同一个 AstrBot 镜像（自带 Python 3.12、ffmpeg）；秘密只在这一会儿挂进来，不长期给 AstrBot 和它的插件看
  tools:
    image: m.daocloud.io/docker.io/soulter/astrbot:v4.29.3
    profiles: ["tools"]
    working_dir: /dafeiyu
    entrypoint: ["python", "-X", "utf8"]
    volumes:
      - ./kit:/dafeiyu/kit:ro
      - ./private:/dafeiyu/private
    networks: [astrbot_network]
networks:
  astrbot_network:
    driver: bridge
```

- **端口一定要带 `127.0.0.1:`**：Docker 映射的端口会绕过 ufw，光靠防火墙挡不住。
- 版本号写死，跟本机路线测过的一致（NapCat 4.18.41、AstrBot 4.29.3），别用 `latest`。
- `ACCOUNT` 那行：镜像的启动脚本看到它不空就带 `-q <小号>` 快速登录；`.env` 里先不写 `NAPCAT_ACCOUNT`（空着就照常出二维码）。10-29 只核过 `docker compose config` 能把它带进容器，真扫码以后的快速登录没测。
- DaoCloud 拉不动时：让他在阿里云「容器镜像服务」控制台拿个人加速地址（要登录控制台复制，停下来叫人），写进 `/etc/docker/daemon.json` 的 `registry-mirrors` 后 `systemctl restart docker`，镜像名去掉 `m.daocloud.io/docker.io/` 前缀；腾讯云服务器试 `mirror.ccs.tencentyun.com`（没实测）。

### C5.3 拉镜像、起来、先把 token 填好

```bash
cd /opt/dafeiyu && docker compose pull && docker compose up -d && sleep 40 && docker compose ps
```

然后**在扫码之前**给 NapCat 的反向 WS 填上 token。`MODE=astrbot` 只在 `napcat/config/onebot11.json` 不存在时写一次（连 `ws://astrbot:6199/ws`，**token 是空的**），之后不再覆盖；扫码登录时 NapCat 会拿它复制出 `onebot11_<小号>.json`，所以扫码前填好就只用改这一份。用镜像里的 Python 改（Alibaba Cloud Linux 3 自带的是 3.6）：

```bash
cd /opt/dafeiyu && docker run --rm -i -v "$PWD":/w -w /w --entrypoint python m.daocloud.io/docker.io/soulter/astrbot:v4.29.3 - <<'EOF'
import json
p = "napcat/config/onebot11.json"; d = json.load(open(p, encoding="utf-8-sig")); tok = open("private/onebot-token.txt").read().strip()
for c in d["network"]["websocketClients"]: c["token"] = tok
json.dump(d, open(p, "w"), ensure_ascii=False, indent=2); print("token 填好了")
EOF
docker restart napcat
```

AstrBot 第一次起来会随机生成初始密码，存进 `private`，不显示：

```bash
cd /opt/dafeiyu && docker logs astrbot 2>&1 | grep -m1 -oP 'Initial password: \K\S+' | tr -d '\r\n' > private/astrbot-initial-password.txt && chmod 600 private/* && wc -c < private/astrbot-initial-password.txt
```

**成功**：两个都是 `Up`；最后打出的字节数是 20 多。
**失败先查**：拉镜像超时 → 换镜像地址；`napcat` 反复重启 → `docker logs napcat` 看是不是挂载目录权限；内存爆了 → `dmesg | grep -i oom`，2G 机器确认 swap 开了。

## C6 把 Skill 拷上去

设置脚本和导入工具在服务器的 `tools` 容器里跑，先把 Skill 整个文件夹拷上去（里面的 `pack\` 就是配置包，不用连 GitHub）：

```powershell
ssh -i "<工作目录>\private\cloud_key" -o BatchMode=yes <user>@<host> "mkdir -p /opt/dafeiyu/kit"
scp -r -q -i "<工作目录>\private\cloud_key" -o BatchMode=yes "<S 的上一级，也就是 dafeiyu-install 文件夹>" <user>@<host>:/opt/dafeiyu/kit/
```

10-28 在 Windows 11 上实测：88 个文件、带中文文件名（`persona\大肥鱼.md` 这些），12.6 秒，名字没乱。以后 Skill 更新了，重跑这两行就行。

## C7 设置后台、接 DeepSeek、建 QQ 平台

全在服务器上、`tools` 容器里跑（10-28 每条都实测通过）：

```bash
cd /opt/dafeiyu; S=kit/dafeiyu-install/scripts/astr_setup.py
for c in account deepseek "bot --ws-host 0.0.0.0" whitelist status; do docker compose run --rm -T tools $S --dir /dafeiyu $c; done
```

- `account`：用初始账号 `astrbot` 和刚存的初始密码登进去，改成 `backend.txt` 里的账号密码。再跑一次会说「已经是那套了」。
- `deepseek`：核余额、建模型、测试通过、关「操作电脑」。
- `bot --ws-host 0.0.0.0`：**云上必须 0.0.0.0**，不然 NapCat 那个容器连不进来（本机路线是 127.0.0.1）。
- `whitelist`：白名单只放大号、大号设管理员。

把后台密码和 NapCat 网页的 token 拷回他电脑（以后他登网页后台、你做桌面快捷方式要用），只拷文件、不显示：

```powershell
scp -i "<工作目录>\private\cloud_key" <user>@<host>:/opt/dafeiyu/private/backend.txt "<工作目录>\private\cloud-backend.txt"
scp -i "<工作目录>\private\cloud_key" <user>@<host>:/opt/dafeiyu/private/napcat-webui-token.txt "<工作目录>\private\napcat-webui.txt"
```

## C8 隧道和扫码

在他电脑上开隧道（后台运行，别占着他的窗口；10-28 在 Windows 11 上实测，两个网页都打得开，关掉 ssh 进程端口就释放）：

```powershell
Start-Process -WindowStyle Minimized ssh -ArgumentList '-i','<工作目录>\private\cloud_key','-o','BatchMode=yes','-o','ServerAliveInterval=30','-o','ExitOnForwardFailure=yes','-N','-L','16185:127.0.0.1:6185','-L','16099:127.0.0.1:6099','<user>@<host>'
```

用 Edge 打开 `http://127.0.0.1:16099/webui?token=<napcat-webui.txt 里那串>`（地址里有 token，提醒他录屏要打码），二维码就在网页上。停下来叫人：「用登着小号的手机 QQ 扫这个码，再在手机上点『登录』」。

**成功**：`docker logs napcat` 出现登录成功，`napcat/config/` 里多出 `onebot11_<小号>.json`（里面的 token 应该和 `onebot-token.txt` 一样），`docker logs astrbot` 里有 aiocqhttp 连上的记录。然后照本机路线第 6 步：大号私聊「在吗」。
**失败先查**：手机弹「账号近期存在安全风险……请根据提示恢复」→ QQ 风控，只能他在手机 QQ 上按提示恢复，恢复后隔一会儿再扫（10-27 原型两次都碰到）；二维码过期 → 网页上刷新，不行 `docker restart napcat`；登上了但 AstrBot 没连上 → 对一下 `onebot11_<小号>.json` 里的 token 和地址（`ws://astrbot:6199/ws`）。

（10-28 实测到「网页后台用 token 登进去、二维码在等扫」为止；扫码以后的登录、连上、掉线都没测：小号当时登在本机测试机上，同一个号不在两处登。）

工作台放好以后（C10，可以提前到这一步做），扫码也能在「云端大肥鱼工作台」里点「扫码登录」：它把服务器上 NapCat 的二维码直接显示在弹窗里，不用开隧道和网页（10-29 只测到二维码能显示）。

## C10 收尾：放「云端大肥鱼工作台」

- 开机自启：`restart: always` 加 `systemctl enable docker`，服务器重启后两个容器自己起来。让他在控制台重启一次服务器验证（可选）。
- 到期日：问他服务器哪天到期（控制台的服务器列表里有），写进 `cloud.txt` 一行 `expire: 2027-10-28`；他说不清就先不写，工作台「到期续费」那项能自己填，快到期会提醒。`cloud.txt` 里服务器目录不是 `/opt/dafeiyu` 的写 `dir: …`，SSH 端口不是 22 的写 `port: …`。
- 工作台：跑 `finish.ps1 -Dir <工作目录>`。它看到 `cloud.txt` 有服务器、这台电脑上没有 AstrBot，就只做工作台：下一份便携 Python（11 MB，放 `<工作目录>\python`），拷工作台，桌面放「云端大肥鱼工作台」。在他桌面会话里打开给他看（`& "<工作目录>\tools\workbench.cmd"`）；它自己开隧道，AstrBot、NapCat 后台都从工作台点开，扫码、掉线、到期、补装、备份、求助信息也都在里面，不用再放 `.cmd` 和桌面说明。细节见 `收尾-自启和掉线.md` 8.4。10-29 在测试机（Windows 11）上实测：收尾 7 秒（Python 从华为云镜像下），工作台双击能开、十项能查、日志、重启大脑、备份、求助信息、记到期日都通；扫码只测到二维码能出在工作台里（小号没在云上登）。
- 快速登录：扫码登上以后，让他在工作台「服务器重启后」那项点「补上」（把小号记进 `.env` 的 `NAPCAT_ACCOUNT`，NapCat 重开一下，以后服务器重启一般不用再扫码）。新装的 C5.2 已经带了 `ACCOUNT` 那一行，「补上」只写 `.env`。
- 加固（先问他）：密钥确认能登以后，关 SSH 密码登录（`/etc/ssh/sshd_config.d/` 里加 `PasswordAuthentication no`，`systemctl reload ssh`）。告诉他：以后密钥丢了还能用控制台的网页终端登，钥匙在 `<工作目录>\private\cloud_key`，换电脑时连 `private` 一起拷走，工作台才连得上。再让他在控制台防火墙里只留 22，把 80、443、3389 这些用不上的关掉（要他点）。

以前装的（桌面是「云端大肥鱼-打开后台.cmd」「云端大肥鱼掉线-扫码.cmd」，没有工作台）：他说「更新大肥鱼」时，换上新 Skill 后跑一次 `finish.ps1 -Dir <云端那个工作目录>` 就有了，那两个 .cmd 和说明会挪进 `<工作目录>\旧版\桌面旧入口\`；再照 C6 把新 Skill 传上服务器（或者在工作台点一次「一键更新」，它会顺手传上去）。

## 验收

同 SKILL.md 第 9 步的 1–5 条。第 6 条换成：双击桌面「云端大肥鱼工作台」能打开，云服务器、大脑、登 QQ 的程序、DeepSeek 四项是绿的。

## 别做的事

- 不装 SnowLuma，不帮他把 SnowLuma 做进 Docker。
- 后台端口不对公网开，安全组不放行 6185、6099、6199、3001。
- 群里插话概率不超过 0.02（云端比本机更怕话多，之前一单云服务器两小时被踢两次时 26 分钟发了 43 条）。
- 不在命令行里传 key 和密码（会进 shell 历史和进程列表）；往服务器写秘密一律走标准输入或 `scp` 文件。
- 不替他买服务器、不替他点支付、不替他重装系统。
