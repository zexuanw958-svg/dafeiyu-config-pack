# 记忆（第 7 步之前准备）

配置包用 LivingMemory 插件做长期记忆，它要一个「嵌入模型」（把一句话变成一串数字、方便以后找回来的模型）。三种选法对应导入时的 `memory`：1 本机 Ollama、2 硅基流动、0 先不要。

## A. 本机 Ollama（默认，导入时 memory = 1）

实测：Ollama 0.40.11 + bge-m3（10-25 P3、10-27 帮人装的一单）。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<S>\install-ollama.ps1" -Dir <工作目录>
```

它做的事：装过就复用；没装就下 `OllamaSetup.exe`（约 1.6 GB，GitHub 加速地址和官网先测速排序），**静默安装**（`/VERYSILENT`，新装到 `<工作目录>\Ollama`，不用管理员）；只在后台起 Ollama 的服务（`ollama.exe serve`，不出窗口，右下角也没有羊驼图标）：它的托盘程序每次启动都会弹自己的聊天窗口，开机、打完游戏恢复都会弹（10-28 测试机），所以开机自启、工作台的修复和恢复也都只起服务。安装包静默装完要是自己开了托盘程序，脚本会把它关掉。bge-m3 没装过就先从国内 ModelScope 下 FP16 GGUF（约 1.1 GB），核确切体积和 SHA256，写 `FROM "<文件路径>"` 后用 `ollama create bge-m3 -f ...` 导入；下载或导入失败才 `ollama pull bge-m3`。最后用 `ollama list` 查模型，再调 `http://127.0.0.1:11434/api/embed` 核向量是 1024 维。新装且没有自定义 `OLLAMA_MODELS` 时，模型放 `<工作目录>\ollama-models`；以前的安装位置和模型目录不搬。安装包和 ModelScope 文件下载会保留半截续传，每 15 秒报进度；总大小未知时只报体积和速度。

**别自己现编安装命令**：这个安装包是 Inno Setup，`/S` 它不认，会停在「Install」按钮上等人点（10-27 测试里 DSH 用了 `/S`，卡了十几分钟）。

**成功**：最后一行「记忆模型能用（向量 1024 维）」。
**失败先查**：下载没下完就重跑（会接着下）；校验失败会删掉重下，ModelScope 下载或导入失败会自动试官方拉取，都失败再查网络。「11434 没起来」让他从开始菜单打开 Ollama；模型不在列表或向量不是 1024 维，不算成功，看最后几行再查。装的时候杀毒软件可能弹「试图开机启动」，让他点允许。
**收尾时别忘了**：Ollama 安装包不会自己加开机启动（坑 8），`finish.ps1` 会补。

## 她什么时候记（要跟观众说清楚）

- **平时聊天**：LivingMemory 攒满 10 轮对话（一问一答算一轮，插件设置 `reflection_engine.summary_trigger_rounds`，默认 10）才总结一次、写进长期记忆。它自己在 `/reset`、`/new` 时会把没攒满的那几轮连同计数一起清掉，从来没进长期记忆，就找不回来了（10-28 实测聊 6 轮就 `/reset`，再问她不记得；10-29 群友「改完人设发 /reset 她就失忆」也是这个）。所以配置包自带「清空不失忆」插件（`astrbot_plugin_dafeiyu_resetkeep`）：`/reset`、`/new` 的回复发出去以后、记忆插件清空之前，先调它的「立即总结」把这几轮存进去（白名单、群各记各的都照它的规矩）。要叫一次 DeepSeek，几秒到十几秒，验收时发完 `/reset` 等一会儿再问。没开记忆时它什么都不做。
- **想起旧事是按眼前这句话去找的**：泛泛地问「你还记得我吗」不一定捞得到，问具体的事（「我家狗叫什么」）就想起来了。他说「平时像失忆、指着问又记得」，先讲这个，再看是不是上面那种没存上。
- **当场记住**：配置包打开了插件的主动写入工具（`agent_tools.enable_memorize_tool`，插件默认关），他说「记住……」她当场存。验收用这个。10-28 实测：「记住，我家的狗叫旺财」→ 她调 `memorize_long_term_memory` 存下「主人的狗叫旺财」→ 回「旺财，记下了」。当时第一次用了 19 秒（bge-m3 还在显卡上、跟 Breeze 抢显存）；改成 CPU 常驻以后一次 50～170 毫秒，不用再等。
- 想改轮数：AstrBot 后台 → 插件 → LivingMemory → 「总结触发轮次」（1–100）。调小记得快，每总结一次多调一次 DeepSeek。

## 记的范围（导入记忆时自动设好）

- 他的 QQ 私聊（和接上了的电脑桌宠）：一份。
- 每个群各记各的：群里的事不会在私聊里冒出来，私聊的事也不会在群里说。
- 没登记过的群、陌生人：不记。让她进群时跑 `astr_setup.py ... whitelist`，会把群同时加进「强制隔离」和「记忆白名单」。

改的是 LivingMemory 的三项：`filtering_settings.memory_scope_mode = global`、`isolated_sessions`（每个群一行）、`access_control.whitelist_enabled = true` 加 `allowed_ids`（他的私聊、桌宠、登记过的群，都写完整会话名）。`astr_setup.py --dir <工作目录> memory-scope` 单独重设，`status` 的「记忆范围」那行看现在是什么样。第 1 步选了「只拿几样」、他原来就装着记忆插件的，这三项不动。

**以前就装着记忆插件的**（老版本是「一个会话一份」）：改完以后私聊里以前记住的事还在旧位置，她召回不到。导入输出 `MIGRATE private-memories` 时替他搬：`astr_setup.py ... memory-migrate` 先预览，`memory-migrate apply` 真搬（只搬私聊那份，插件搬之前自己备份数据库）。

## 对电脑的影响、打游戏（他多半会问）

`install-ollama.ps1` 把 bge-m3 固定在 CPU 上跑（`PARAMETER num_gpu 0`），新装的 Ollama 还设了常驻（`OLLAMA_KEEP_ALIVE=-1`）。10-28 测试机实测（i9-13900HX 笔记本，RTX 4060 8 GB）：

- **不碰显卡**：显存一点不占。放显卡上反而跟本机语音 Breeze 抢显存，空闲一会儿后第一下要卡 7～11 秒。
- **CPU**：没人说话时基本为零（10 秒里只用 0.02 秒 CPU）；她每回一条消息算一次，50～170 毫秒，玩游戏感觉不到。
- **内存**：常驻约 1.2 GB。16 GB 以上的电脑不用管，8 GB 的电脑开大游戏前建议点打游戏模式。
- 真正吃显卡的是本机语音 Breeze（4060 上常驻约 4 GB 显存），见 `语音-Breeze.md`。

**打游戏模式**（工作台「打游戏模式」按钮，选了本机语音或本机记忆才有）：先在后台关掉语音总开关、停掉记忆插件，再关 Breeze 和 Ollama，约 5 秒。这段时间她照样回消息（实测 3 秒），只打字，说的事不进长期记忆，以前记住的都在。打完点「打完了，恢复」，约 25 秒，程序和开关都回来。没点恢复就关机重启也没事：开的时候在启动文件夹放了「大肥鱼-打完游戏恢复」，开机自己恢复、恢复完删掉自己。

为什么不直接关程序：只关 Ollama，记忆插件每条消息都会先连它、重试七八秒才放弃（10-28 实测一条回复 9 秒，其中 7.5 秒在等）；只关 Breeze，三条里那条该发语音的也要先重试一阵才改发文字。所以先跟后台说一声再关。

## B. 硅基流动（导入时 memory = 2）

1. 停下来叫人：让他去硅基流动官网注册、实名（如果要求）、在「API 密钥」里新建一把。你可以帮他打开网页。
2. 建 `private\sf-key.txt`，记事本打开让他粘、保存。
3. 回答文件里加 `"siliconflow_key_file": "<工作目录>\\private\\sf-key.txt"`。

模型是 `BAAI/bge-m3`。Vol.04 写文档时硅基流动价格页标的是免费，以他看到的为准。

**成功**：导入工具结果里记忆那一项打勾（`RESULT memory=ok`）。导入工具会先拿这把 key 试一次，试通了才把记忆插件指过去、打开。
**失败先查**：key 粘错；账户被要求实名还没做。
**key 文件是空的**（还没粘、粘了没保存）：导入工具不建空 key 的记忆模型，记忆插件关着，结果是 `RESULT memory=fail reason=no-key`，照 `next` 让他粘好再跑 `--only memory`。他后台里本来就有一把硅基流动 key（上一期 bat 装的记忆，或他自己在后台填的），这次没给 key 也会接着用那把。

**别留半截**：10-28 群友那台「插件配的是硅基流动、key 空着」，插件看着开着，其实一句也记不住（老版本导入工具在 key 文件只有空格时会建一个空 key 的模型，答案文件没写 `memory` 时还会默认当成 2）。现在导入工具、`astr_setup.py status`、工作台、体检都会认出这种情况：status 第 3 行写「记不住事」，工作台记忆那项亮红灯。他要么给 key，要么改本机（A），要么先不要（C），三选一，别停在中间。

## C. 先不要（导入时 memory = 0）

导入工具会把记忆插件关掉（以前记住的不删；10-28 以前的导入工具填 0 只打一句「先不装」，开着的插件不动）。以后想加，准备好再重跑一次导入就行。回答文件里干脆没写 `memory` 的，导入工具不动记忆（`RESULT memory=skip reason=not-in-answers`）。
